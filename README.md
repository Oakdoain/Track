# 第三轨：隔音室谋杀案

> Third Track: The Soundproof Room Murder

《第三轨》是一款以案件档案和 Narrative Graph 为主要界面的流程图式推理互动小说。玩家阅读记录、选择调查方向，从正文中提取预设关键词，并尝试把关键词连接到相关节点；连接结果会推动调查、形成错误推断，或仅提示当前关系无效。

## 游戏概念

玩家以调查者身份从档案库调阅案件，并在同一套案件终端中阅读剧情、查看线索和组织推理。

- **T-00：调查流程训练档案**：用于介绍音频记录、调查分支、回溯、关键词和图谱连接。
- **CASE 01：《隔音室谋杀案》**：当前提供“控制室备份录音”Vertical Slice。
- **后续案件**：仍处于开发计划阶段。

完成 T-00 后，完成状态会写入独立的案件进度文件；返回档案库时，CASE 01 才会开放。重新开始教程或加载较早的教程存档不会把已完成状态改回未完成。

## 核心玩法

1. 阅读剧情或档案节点。
2. 选择下一步调查行动。
3. 点击正文中带下划线的配置关键词，将其加入当前案件的关键词实例。
4. 在调查图谱中选择关键词，再选择目标节点。
5. 系统按案件的 `keyword_rules.json` 判断连接结果。
6. 使用回溯返回本次会话实际经过的上一剧情节点，或从错误节点返回最近安全节点。

### 正确连接

- 建立永久关键词连线；
- 解锁配置的调查节点；
- 已参与永久连接的关键词实例不能删除。

### 错误推断

- 进入配置的错误解释节点；
- 说明现有证据可以支持什么、不能支持什么；
- 错误节点不自动覆盖最近安全状态，可返回最近安全节点。

### 连接无效

- 显示无效反馈；
- 不建立永久连线；
- 不进入错误节点，也不改变安全节点。

这些结果只对当前数据中已经配置的关键词和目标生效，不代表完整案件的全部推理规则已经完成。

## 视觉与界面方向

界面采用蓝白案件档案系统风格，结合流程图小说、美式调查报告和旧式文本数据库的视觉语言。主要特征是细线边框、小圆角、低装饰密度，以及中文衬线标题配合英文无衬线或等宽编号。

## 技术栈

- Godot 4.7.1
- 静态类型 GDScript
- JSON 驱动的案件、节点、线索、图谱布局和推理规则
- OGG / MP3 音频
- 预生成 JSON 音频波形缓存
- Godot `user://` 下的本地存档、设置和案件元进度

项目没有 `addons/` 目录，也未接入第三方 Godot 插件。

## 运行项目

1. 安装 Godot 4.7.1。
2. 克隆或下载本仓库。
3. 使用 Godot 打开根目录中的 `project.godot`。
4. 等待字体、图标、图像和音频资源导入完成。
5. 运行项目。

项目主场景是 `res://scenes/AppRoot.tscn`。正常启动首先显示标题页，而不是直接实例化案件 `MainUI`。首次开始游戏会进入档案库，再由玩家选择当前可用的案件。

`project.godot` 当前配置的 Autoload：

- `StoryManager`：基础剧情数据服务；
- `AudioManager`：跨页面复用的音频加载与播放服务。

## 案件数据结构

`data/cases/cases.json` 是案件注册表。每个案件切片目前可包含：

- `case.json`：案件 ID、切片 ID、标题和起始节点；
- `nodes.json`：剧情节点、正文、选项、节点类型、资源引用和安全存档属性；
- `clues.json`：节点右栏使用的文本或档案线索；
- `audio_clues.json`：音频 ID、文件路径、显示信息和时间标记元数据；
- `keyword_rules.json`：正文关键词锚点，以及关键词到目标节点的连接结果；
- `graph_layout.json`：图谱画布尺寸和剧情节点坐标，不重复保存剧情正文。

`CaseDataLoader` 会先验证案件注册信息，再按 `data_path` 加载这些文件。缺少可选资源时会给出 warning；案件入口或节点主数据无效时则停止进入该案件。

## 开发原则

- 案件内容和运行状态分离，运行时发现内容不写回剧情 JSON。
- 每个教程阶段尽量只要求一个主要动作。
- 可提取关键词嵌入原正文，仅用下划线和轻量状态区分。
- 推理反馈需要说明证据边界，避免把可能性写成事实。
- 错误或失败节点不覆盖最近的安全状态。
- 图谱布局数据不重复保存剧情正文和连接规则。
- 不依靠大量无关线索制造难度。
